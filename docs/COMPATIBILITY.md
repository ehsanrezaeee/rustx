# Compatibility and limitations — 12 November 2026

Rust owns visible state, layout, shaping, editing and scene. Generated HTML/JS and transparent browser semantic/input controls remain necessary. Browser DOM measurement never controls visible geometry. This is canvas rendering with a platform bridge.

- Stage 3 supplies the finite widget vocabulary and composed helpers. Raw nodes expose controlled props/events; use `tabs`, `select`/`combobox`, overlays, table, scrolling and toast helpers for their stateful interaction patterns. Styling is a finite typed API, not HTML/CSS/React compatibility. Popups are retained Rust overlays.
- Shared editing supports grapheme/UTF-16 selection, shaped bidi movement, composition grouping/cancel and bounded undo/redo. Native/browser adapters forward real platform events. Automated input is not real OS IME evidence; candidate positioning, every bidi/navigation pattern, autofill/password managers and mobile keyboards need actual target testing. Passwords are redacted from semantic/inspector/debug projections.
- Ordinary text offers opt-in `.selectable(true)` with a retained read-only selection model and Rust-painted highlights. Its browser selection/copy bridge uses one transparent read-only multiline representation. Default text remains outside the Tab order. Full browser Find/translation/extension behavior is outside this finite selection API.
- Browser semantics carries roles/names/value/state/relationships, live feedback, focus and virtual membership. Native AccessKit source supplies Windows UIA/macOS accessibility. No NVDA/Windows browser, VoiceOver/Safari or NVDA/native Windows form completion has been certified. Metadata and adapter tests are insufficient to close those gates.
- HTTP is bounded, scoped and supports standard methods/headers/body, multipart, timeout/cancel, decoding and explicit status policy. Services include pull streaming, WebSocket, query cache/mutations, typed routes/history/hash, versioned persistence/migrations, files/clipboard/print and timers. Browser permissions/CORS/CSP still apply. Native service availability depends on OS utilities; real native clipboard/file/print permission and denial matrices remain open. Cancellation rejects late results; native blocking I/O or an OS dialog can continue until its underlying operation exits.
- Stream/WebSocket bounds limit delivered/queued framework data. Browser networking and OS/driver internals have their own buffers. No fabricated upload progress, automatic mutation replay, or automatic socket reconnect is provided. See STAGE3_SERVICES.md.
- Hash routing supports reload without server rewrites. The development server also has extensionless SPA fallback and deterministic fault endpoints. It is a loopback development tool, not a production deployment. Native history is in-app history, not browser history. Cross-device persistence needs an application backend.
- Stage 2 layout/font/cache/virtualization/drawing limits remain in STAGE2.md. Monochrome emoji fallback, fixed-height/index-keyed virtual lists and a finite style/text model remain intentional boundaries. No complete font/effect conformance or total process/GPU memory bound is claimed. Native and browser renderer/DPI/device-loss parity still needs the full target matrix.
- Existing actual Mac/browser engine evidence is retained. Stage 3 evidence names the exact rebuilt Wasm. WebKit automation is not actual Safari; 390px browser automation is not a physical mobile task. Prior Firefox startup/profile/sandbox and bundled Chromium CDN failures remain under evidence/history; they are not passing browser evidence.
- No actual Windows machine/session, Windows binary distribution, external clean-machine replay, full Safari/mobile matrix or fixed-hardware release benchmark has passed. Native Mac startup and cross-compilation cannot substitute for Windows execution.
- Stage 4 supplies `.rustx` formatting/editor support, standalone CLI project generation, hashed web distribution/offline shell, opt-in diagnostics and real editable-source compilation. The compiler is a separate local service with tested Mac isolation; Linux remains unverified and Windows compiler isolation is unavailable. Normal applications require no Python/Node runtime. Full limits are in STAGE4.md and stage4/PLAYGROUND.md.
- Live JSONPlaceholder browser success is recorded separately from fixtures. The homepage presets stay labelled precompiled; the real playground compiles visitor edits and reports actual errors. Flagship acceptance still needs human AT and shared-source Windows tasks.
- Readable source and repeatable Rust/RustX/Prettier checks are delivered. Measured desktop budgets, comparative benchmarks and supply-chain/license findings remain in the authoritative ledger; no threshold is relaxed to claim a pass.

No universal speed comparison, production-readiness claim or full stage acceptance is implied. ACCEPTANCE.md is authoritative.
