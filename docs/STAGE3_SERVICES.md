# Stage 3 service API and adapter limits

The public types are reexported by `rustx::prelude::*`. Application developers write Rust; browser adapters in `web/services.js` call platform APIs. This document describes source behavior; use the acceptance ledger for actual target evidence.

```rust
let request = http.request("POST", "/api/echo")
    .json(&vec![1, 2, 3])
    .timeout(std::time::Duration::from_secs(3));
let task_scope = cx.clone();
tasks.spawn(&cx, async move {
    let result = request.send(&task_scope).await
        .and_then(HttpResponse::error_for_status)
        .and_then(HttpResponse::text);
    // Set a scoped signal from result.
})?;
```

`HttpClient::get` remains the Stage 1 callback API. `request(method,url)` adds GET, HEAD, POST, PUT, PATCH, DELETE and OPTIONS. Builders accept validated headers, bytes/text/JSON/multipart, credentials, timeout and response limit. `send_callback` is available without a future executor. `send` returns a future whose drop cancels the request. `TaskQueue` owns futures by scope; hosts poll it after input and service completions, without idle frame loops. Scope disposal drops tasks and cancels requests. HTTP status is preserved until `error_for_status` is applied. Text/JSON decode, transport, timeout, cancellation, admission and size errors remain distinct. Diagnostic Debug output excludes URLs, headers and body contents. A GET-only capability report rejects the new request API explicitly.

HTTP limits: 16 concurrent requests, 32 queued commands, 8 KiB URLs, 32 outbound headers, 1 MiB upload/download, at most 10 seconds per request, at most 64 response headers/32 KiB header content. Browser credentials default to same-origin. Browser Fetch enforces CORS, forbidden headers, redirects, mixed content and CSP; a generic browser network failure does not identify a specific CORS cause. Native HTTP does not provide browser security equivalence. Native cancellation suppresses results immediately but blocking DNS/I/O can continue until adapter timeouts; request-worker admission remains bounded. No implicit retries are performed, especially for mutations. Multipart boundaries are generated per request and header injection is rejected. Upload progress is not fabricated.

`ServiceClient::call` creates one-shot typed capability work. `subscribe` keeps location/stream/socket callbacks registered for the scope. Both return a service ID. `cancel` removes the callback and releases host resources. Results are `ServiceValue` or explicit `ServiceError::{Unavailable,Denied,Cancelled,Quota,TooLarge,Busy,Invalid,Failed}`. `ServiceCommand` uses a versioned envelope and safe numeric IDs; malformed/skewed/stale results cannot consume another live callback. At most 32 service callbacks/resources/commands are retained. Outbound command Debug output is redacted. Services transfer owned buffers rather than borrowed Wasm memory.

`ServiceOperation` covers clipboard read/write, explicit file selection/download, versioned storage read/write/remove, location watches, navigation/history, timers, pull streams, WebSockets and printable semantic text. `HostServices.capabilities()` reports browser API availability as a typed `ServiceCapabilities` handshake. `ServiceClient::connect` rejects skewed or duplicate reports and distinguishes unavailable, denied and failed capabilities before queueing. Native reports detect required OS utility availability. Permission errors are also reported from the attempted operation. Clipboard, picker, popup and download commands are pumped synchronously from user events so their adapters retain browser activation where the platform permits it; permissions and activation requirements still apply.

`ServiceOperation::Timer` and `ServiceClient::sleep(scope, duration)` expose scoped one-shot scheduling from 1 ms to 60 seconds. Dropping the future, cancelling the operation or disposing the scope clears the browser timeout or wakes/cancels the native timer worker. A service completion pumps the local task queue without continuous rendering. The delay is a scheduling request rather than a real-time guarantee.

Browser persistence uses IndexedDB transactions in database `rustx-state`, store `records`; schema migration is an explicit Rust `migrate_record` operation. Native persistence uses a RustX directory under LOCALAPPDATA, XDG_DATA_HOME or HOME/.local/share, with hex-encoded keys. Native keys are limited to 124 UTF-8 bytes so the encoded filename and `.json` suffix fit a 255-byte filesystem name; browser keys to 1 KiB. Stored values are at most 1 MiB; the native store has an 8 MiB aggregate quota. Browser storage denial/quota and future schema versions are distinct errors. This is local persistence; it does not synchronize between devices.

File transfer is bounded to 1 MiB. Browser files require the visible OS file picker; downloads carry a filename and MIME type and release object URLs. Native adapters invoke OS file open/save dialogs; file filters/MIME detection currently have a narrower native contract (returned MIME defaults to application/octet-stream). Native clipboard uses pbcopy/pbpaste on macOS, PowerShell on Windows, and wl-copy/wl-paste on Linux; missing utilities report unavailable. Native OS dialogs and clipboard processes can outlive scope cancellation; their late results are discarded. Browser printing builds a separate semantic h1/pre document with textContent and invokes the print dialog. Native printing invokes TextEdit's print dialog on macOS, the registered Print verb on Windows, and lp on Linux; these paths require actual target/printer verification.

Pull downloads use `StreamOpen` subscriptions followed by explicit `read_stream(id)` demand. Each read yields at most 64 KiB, tracks actually received bytes and optional server Content-Length, and releases the reader at end or cancellation. No chunk is requested until the consumer asks. Total response and timeout bounds still apply. These are bounded byte streams rather than a streaming JSON parser.

WebSockets expose open/message/error/close events. Incoming and outgoing messages are at most 64 KiB, queued outgoing bytes at most 256 KiB, native command queues at most eight messages, and native result queues at most 32 events. Browser bufferedAmount rejects excess sending; the browser WebSocket API cannot provide transport-level incoming backpressure. Native adapters use pinned tungstenite with rustls for ws/wss and bounded frames/messages. Reconnection is an explicit application policy. Closing/unmounting removes listeners and releases resources. Relative socket URLs resolve against the app's origin in browsers and http://127.0.0.1:3000 in the native development host.

`QueryCache<T>` provides typed Idle/Loading/Success/Error signals, key-based deduplication, explicit stale milliseconds and host clock, cache invalidation and refetch. One owner scope owns requests so removing one observer does not cancel another observer's work; the last observer leaving cancels pending work. Capacity is 1–64 keys and at most 64 observers per key; inactive oldest entries can be evicted. A key cannot silently change its URL. Generations reject superseded results. `Mutation<T>` exposes Idle/Pending/Success/Error, cancellation and stale-result rejection, with no automatic retry. Invalidation is explicit; this finite utility is not an exhaustive query framework.

`Router<T>` matches typed route values with `:params`, final `*path`, decoded UTF-8 query pairs and fragments. History and hash modes expose `Signal<RouteState<T>>` with found/not-found/error states, navigation guards, back and forward. Guards run before programmatic navigation; browser Back cannot always be cancelled. Browser hosts need SPA rewrites for history URLs; the fixture server includes extensionless fallback. Hash routes work without rewrites. Native history is bounded to 128 entries and uses the same route signal; it is not an operating system URL registration.

`node scripts/test-stage3-services.mjs` exercises actual Rust loopback fixtures through production Fetch and WebSocket adapters. Its injected permission-denial branch is separately labeled as a contract test. It does not certify browser permissions, real IME, assistive technology, native Windows or physical mobile behavior.
